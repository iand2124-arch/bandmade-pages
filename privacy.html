BandApp / Privacy

Your information.
Your band’s business.

Effective date: 1 November 2026 · Operated by Ian Downes, Australia

This policy describes the private BandApp application and this public information website. BandApp is a personal tool for managing bands, songs, set lists, contacts and events.

Information held by BandApp

BandApp stores information entered by its authorised users, such as band and member details, contact information, song charts, set lists, event names, venues, addresses, dates, times and notes. Users should only enter information they are authorised to use.

Google Calendar access and use

Connecting Google Calendar requires the Google account holder’s consent. BandApp requests the calendar.events permission, which allows it to view and edit events on calendars accessible to that account. This permission is broader than just the events created by BandApp; the implemented integration uses it to create, update and delete the corresponding BandApp events in its configured calendar.

For synchronisation, BandApp sends event titles, band names, start and end times, venues, addresses, notes and reminder settings to Google. It stores the Google event identifiers returned by Google so later edits or deletions can target the corresponding events. The current integration does not import your Google Calendar event collection into BandApp, and does not request Gmail, Google Drive or Google Contacts access.

Google authorisation credentials, including access and refresh tokens, are stored on the private server so synchronisation can continue without repeated sign-ins. They are not included in this public website or its repository.

Storage, access and retention

App information is held on the owner’s privately managed server and may be included in its backups. Access is limited to the owner and users authorised to access the private app. Credentials are kept separately from the public website and public source repository.

Information is retained while needed for the app’s personal and band-management purposes, or until the owner removes it. Removing a record from the active app does not necessarily remove it immediately from existing backups; backup copies remain until those backups are replaced or deleted.

Sharing and third-party services

Calendar synchronisation sends the event details described above to Google. Spotify matching sends song titles, artist names and search queries to Spotify to find candidate recordings. Calendar information is not used for Spotify matching.

BandApp does not sell Google user data, use it for advertising, or use it to train artificial intelligence or machine-learning models. Its use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

The public information website is hosted by GitHub Pages. It has no added analytics, advertising, contact forms or tracking scripts. GitHub may process visitor information, including IP addresses and request logs, under its privacy statement. Following links to Google, Spotify or GitHub is subject to those services’ own policies.

Disconnecting Google Calendar

You can revoke BandApp’s Google access through your Google Account’s third-party connections. Revocation prevents future authorised API access; it does not automatically delete existing calendar events or records already stored in BandApp. The owner can also remove saved authorisation credentials from the private server.

Access, corrections and deletion

Authorised users can edit or remove records through the available app controls, or contact Ian Downes using their existing contact channel to request access, correction or deletion. Deleting a synced event in BandApp attempts to delete its linked Google Calendar event; if synchronisation fails, the calendar event may need to be removed separately.

For a general privacy enquiry, you can open an issue in the public information-site repository to request a private contact channel. Do not include private event details, personal records, passwords or tokens in a public issue.

Policy updates

This page will be updated if BandApp’s data practices change. The effective date above identifies the current version.
